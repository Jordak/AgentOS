# Core Root and Publishable File Set Boundary

AgentOS Core means the public-safe reusable AgentOS layer under `$root/os/`; root-level files and sibling directories such as `README.md`, `AGENTS.md`, `CLAUDE.md`, `DOMAIN.md`, `docs/`, `scripts/`, and `.github/` are publishable repository-managed support files, but they are not part of the Core Root. Policies that apply beyond `$root/os/`, such as publication, symlink, CI, installer, validator, and public export rules, should use terms such as Publishable File Set, AgentOS-managed file set, or managed repository paths outside top-level `personal/` instead of broadening Core to mean the whole repository.

This preserves the existing Core/Personal Overlay model from ADR 0001, where Core and Personal Overlay have mirrored AgentOS layers under `os/` and `personal/os/`. It also keeps necessary root compatibility: `.github/` must stay at repository root for GitHub, `README.md` must stay root-discoverable, root adapter files must be visible to agent harnesses, `DOMAIN.md` stays at the repository domain-doc convention path, and `scripts/` remains the reviewed command surface used by docs, hooks, CI, and publication workflows.

The stricter root layout option, where only `os/` and `personal/` remain at the repository root, is deferred. It would require moving conventional GitHub, README, adapter, domain, script, and ADR paths for naming tidiness without materially improving the privacy boundary. The privacy boundary is instead enforced by clear terminology: Core Root is `$root/os/`; publishability and managed-file checks cover the broader Publishable File Set.
